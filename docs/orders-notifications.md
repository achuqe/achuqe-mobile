# შეკვეთები და აპშიდა ბიზნეს-შეტყობინებები

## პირველი ვერსიის მიზანი

„აჩუქე“-ს პირველ შეკვეთის ნაკადში მომხმარებელი პროდუქტის გვერდიდან შექმნის **შეკვეთის მოთხოვნას**. ეს ჯერ არ წარმოადგენს საბარათე გადახდას: მომხმარებელი მიუთითებს საკონტაქტო და მიწოდების მონაცემებს, შემდეგ ბიზნესი იღებს აპშიდა შეტყობინებას და თავად ადასტურებს ან აუქმებს შეკვეთას.

## მომხმარებლის ნაკადი

მომხმარებელი ირჩევს პროდუქტს, აჭერს „შეკვეთის შექმნას“, ავსებს სახელს, ტელეფონს, მიწოდების მისამართს და რაოდენობას. დადასტურების შემდეგ იქმნება ახალი შეკვეთა `pending` სტატუსით. მომხმარებელი ხედავს წარმატების ეკრანს; მომდევნო ვერსიაში დაემატება მისი შეკვეთების ისტორია და გადახდა.

## ბიზნესის ნაკადი

ახალი შეკვეთისას პროდუქტის მფლობელი ბიზნესი იღებს შეტყობინებას აპში. ბიზნესის დაფაზე გამოჩნდება ახალი შეკვეთების რაოდენობა, ხოლო შეტყობინებების ცენტრში — პროდუქტის სახელი, რაოდენობა, სრული თანხა, მყიდველის სახელი და მოთხოვნის დრო. ბიზნესს შეუძლია შეკვეთა გახსნას, წაიკითხოს მიწოდების ინფორმაცია და შეცვალოს სტატუსი.

| სტატუსი | მნიშვნელობა | ბიზნესის მოქმედება |
|---|---|---|
| `pending` | ახალი შეკვეთა; ბიზნესის პასუხს ელოდება | დადასტურება ან გაუქმება |
| `confirmed` | ბიზნესი იღებს შეკვეთას | მომზადების დაწყება |
| `preparing` | შეკვეთა მზადდება | გადაცემისთვის მომზადება |
| `shipped` | შეკვეთა გაიგზავნა ან გადაეცა კურიერს | მიწოდების დადასტურება |
| `delivered` | შეკვეთა დასრულდა | მხოლოდ ისტორიის ნახვა |
| `cancelled` | შეკვეთა გაუქმდა | მხოლოდ ისტორიის ნახვა |

## მონაცემები და დაცვა

თითოეული შეკვეთა ინახავს მომხმარებლის ID-ს, ბიზნესის ID-ს, პროდუქტს, ერთეულის ფასს, რაოდენობას, ჯამს, საკონტაქტო სახელს, ტელეფონს, მისამართს და სტატუსს. შეტყობინება უკავშირდება მხოლოდ შესაბამის ბიზნესს; სხვა ბიზნესს არ შეუძლია მისი წაკითხვა, წაკითხულად მონიშვნა ან შეკვეთის სტატუსის შეცვლა.

## პირველი ვერსიის საზღვრები

აპშიდა შეტყობინება ნიშნავს, რომ იგი ჩანს „აჩუქე“-ს გახსნისას. ტელეფონის background push-შეტყობინება, საბარათე გადახდა, თანხის დაბრუნება და კურიერის API ინტეგრაცია შემდეგი ეტაპებია.
